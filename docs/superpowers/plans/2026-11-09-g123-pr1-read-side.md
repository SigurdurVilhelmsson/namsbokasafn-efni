**Goal:** the module route can compute, for every eligible chemistry segment, the AI term groups the spec's §6 allows,
and sends them as `suggestions` on that segment. Nothing writes a switch row yet, so in production no segment carries
the key and editors see no change.

**Architecture:** an independent server script first measures the reference sets (task 1), so the view's code is
later checked against numbers it did not produce. Then a pure placement file (task 2), a server-own log reader with
the drop (task 3), migration `057` (task 4), the eligibility and offered-set service (task 5), the route's step 5
(task 6), and the corpus acceptance checks 1–3 (task 7).

**Tech Stack:** as in the index.

**Spec:** [G1.23 spec](../specs/2026-11-02-suggestion-view-design.md) §5, §6, §9.1–9.3, §10, §12; the G1.1 + G1.2 spec
§5.4 step 5, §5.13, §11.

## Global Constraints

The index's Global Constraints apply. In addition, for this PR:
- **No route file** names `module_openings`, `module_opening_inflight` or `opened_at_ms` (`researchBoundary.test.js`).
- **`suggestions` appears only on segments that have a group or a tag** (index decision 7).
- **The reference script (task 1) must not require `suggestionLogs.js`, `suggestionView.js` or
  `suggestion-placement.js`.** It is the independent oracle.

## Review Focus

1. **A module with a damaged log** gets the module without `suggestions` and one warning, and the next module is
   unaffected. → task 3 (reader) and task 6 (route).
2. **Appendices** (`chapter = -1`, dir `appendices`) read their logs like any chapter. → task 3.
3. **A segment whose in-flight edit is the newest row** offers groups on that edit's text, and tags only the
   accepted ops of a *pending* edit, never of an approved one. → task 5.
4. **A segment id that occurs twice** gets nothing on either occurrence, and a sibling in the same module still gets
   its groups. → task 5.
5. **The research file being unreadable** changes nothing in the module JSON. → task 6.

### Task 2: The placement rule (`suggestion-placement.js`)

**Files:**
- Create: `server/public/js/suggestion-placement.js`
- Test: `server/__tests__/suggestionPlacement.test.js`

**Interfaces:**
- Produces (global `suggestionPlacement` and `module.exports`):
  - `MARKER_TOKENS: readonly string[]` = `['[[', ']]', '**', '__', '<!--', '|']`
  - `hasMarker(s: string) -> boolean`
  - `applyOnce(text, find, replace) -> string | null`: `null` unless `find` occurs exactly once (the
    `chainChanges` test: `indexOf`, then `indexOf(find, at + 1) === -1`).
  - `placeGroup(text, group) -> { ok: true, result: string, spans: [{ opId, start, end }] } | { ok: false, reason:
    'marker' | 'not-unique' | 'overlap' }`. Applies the group's changes in order; each span is the change's `find`
    in **`text`'s** coordinates, mapped back through the earlier changes' length deltas. A change found inside an
    earlier change's `replace` is `overlap`.
  - `visibleGroups(text, groups) -> [{ group, spans }]`: `placeGroup` on `text` for each group independently, in
    order; then a group whose spans overlap an already-kept group's spans is dropped (the earlier in chain order wins,
    spec §6.5).
  - `tagSpans(text, changes) -> [{ opId, start, end }]`: for each change in order, its `replace` must occur exactly
    once in `text` outside the spans already tagged; otherwise that change gets no tag (spec §7, "GG tags after save").

**Interfaces:**
- Produces:
  - `DROPPED_CATEGORIES: readonly string[]` = `['agreement']`
  - `readModuleLog({ book, chapter, moduleId }, { booksRoot, repoRoot } = {}) -> { ok: true, chains: Map<string,
    record[]>, labels: Map<string, { en, is }> } | { ok: false, reason: 'absent' | 'malformed' | 'unreadable' }`.

    full chain; a group with a marker token in any `find` or `replace` is left out.
  - `firstBeforeSha256(log, segmentId, occurrence) -> string | null`: the first record's `beforeSha256`, before the drop.

- [ ] **Step 3: Implement the reader**

Path: `<booksRoot>/<book>/02-mt-revised/<chapterDir(chapter)>/<moduleId>-changes.jsonl` and `-revision.json`. Organic
returns `absent` before any read. A record is valid only with exactly the 15 keys the logs carry (`module, segmentId,

`revision.rulingSet.sha256`; parsed labels are cached in a module-level `Map` keyed `path + sha256`. Warnings use the
server logger with `{ book, moduleId, reason }` only.
