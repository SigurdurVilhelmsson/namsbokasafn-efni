# §C248 + G1.11: toolbar dialect and bracket-marker save gate — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The editor's formatting toolbar writes the markup dialect each segment already uses, and the save gate refuses or announces bracket-marker damage.

**Architecture:** One taxonomy file (`tools/lib/marker-types.json`) feeds a pure UMD module (`server/public/js/marker-integrity.js`) that classifies dialects, picks toolbar pairs and checks markers; `segment-validation.js` calls it, so all five existing consumers (two panes, `servedEdit`, propagation, the localization routes) get the rules. The browser receives the taxonomy from a route that wraps the JSON. Inject exports its own dialect test so a corpus test can hold the browser and inject in step.

**Tech Stack:** Node 22 (CommonJS in `server/`, ESM in `tools/`), vanilla browser JS (UMD), Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-21-c248-g111-toolbar-dialect-and-marker-gate-design.md` (approved 2026-11-21). Read it; this plan argues from it.

## Review Focus

1. **Nested markers** (`[[b:… C[[sub:4]]H[[sub:10]] …]]`): every count is by `[[type` prefix, never by parsing; Task 3 carries the nesting control.
2. **An unchanged save of any real segment** must produce no new block: Task 4 runs `validateStructure(en, is, is)` over every chemistry segment pair and asserts `blocked` gains nothing.
3. **Literal characters** (`σ*`, `~10`, `~150 torr`) must never classify a segment as legacy or fire rule 5: Tasks 2 and 3 pin them with chemistry's own strings.
4. **The E2E row pickers** (`middleVirginRows` and `helpers/segments.js`) choose rows on which `validateStructure` returns nothing; new warnings must not empty their candidate sets — Task 5's E2E run of the touched specs proves it.
5. **A keyboard wrap with no selection** inside a new-format row writes `[[b:]]` and the save is refused with the empty-marker message, not a server error: Task 5's E2E.

### Task 3: The marker rules

**Files:**
- Modify: `server/public/js/marker-integrity.js` (add `scanMarkers`, `checkMarkers`)
- Test: `server/__tests__/markerIntegrity.test.js`

**Interfaces:**
- Produces:
  - `scanMarkers(text: string): {counts: Object<string, number>, spaced: Object<string, number>, empty: Object<string, number>, exact: string[], open: number, close: number, unknown: string[]}` — `counts` by `/\[\[([A-Za-z]+)(?=[:\]|])/g`; `spaced` by `/\[\[([A-Za-z]+): /g`; `empty` by `/\[\[([A-Za-z]+):\]\]/g`; `exact` = the `TABLE`/`lb`/`rb` marker strings (`/\[\[(TABLE|lb|rb):[^\]]*\]\]/g`); `open`/`close` = `[[` / `]]` counts; `unknown` = distinct types not in `TYPES`.
  - `checkMarkers(enText: string, originalIs: string, editedIs: string): {blocked: Array<{code, params}>, warnings: Array<{code, params}>}` (arrays, possibly empty). Codes and params:
    - `marker-spaced` `{type}` — per type, `spaced` edited > original.
    - `marker-unbalanced` `{open, close}` — edited `open !== close`.
    - `marker-empty` `{type}` — per type except `lb`/`rb`, `empty` edited > original.
    - `marker-dropped` `{type, from, to}` — per structural type, edited count < min(original, English); `from` = that minimum.
    - `marker-dropped` `{marker}` — each `exact` string present in both original and English but absent from edited.
    - `formatting-dropped` `{type, from, to}` — per presentational type, same comparison as structural (warning).
    - `marker-unknown` `{type}` — per type in edited's `unknown` (warning).
    - `marker-lb-rb` `{lb, rb}` — edited `lb` count ≠ `rb` count (warning).
    - `legacy-wrap` `{direction:'added', marker}` — edited is bracket dialect and the count of a legacy wrap in edited exceeds original's; `marker` ∈ `'**' '*' '__' '~' '^'` (italic counted by `/(?<![*\w])\*[^*\s][^*\n]*\*(?![*\w])/g`, the others by Task 2's patterns) (warning).
    - `legacy-wrap` `{direction:'flip'}` — original not bracket dialect, edited bracket dialect, `hasLegacyMarkup(edited)` (warning).
