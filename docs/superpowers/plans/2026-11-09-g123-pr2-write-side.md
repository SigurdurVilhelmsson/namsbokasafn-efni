> superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax. **The tree

> [the index](2026-11-09-g123-suggestion-view.md) and [PR1's plan](2026-11-09-g123-pr1-read-side.md) (its "Handoff to
> PR2" binds this plan) first.

**Goal:** the server records every outcome of a suggestion: the groups a save took (on the edit row), each reject
(its own row, and a `suggestion-reject` event), and each group still open when a segment is finished (its own row, and
a `suggestion-left-open` event); and it marks an `ai-suggestion` item `validated` only when the claim checks out.
Still nothing writes a switch row, so production is unchanged.

**Architecture:** four tasks on four seams that exist on `main`: `saveOnServedBase` → `saveSegmentEdit` (the only
write path for edit rows: `servedEdit.js:217` is `saveSegmentEdit`'s one caller), `CLAIM_VALIDATORS` in
`researchEmission.js`, a new reject route, and the two finishing acts (`acceptanceService.acceptSegment`, called only at
`routes/segment-editor.js:1006`; `segmentEditor.approveEdit`, called only at `:1247`). The editing record is written
and committed first; each research call runs after and never changes the response.

**Tech Stack:** as in the index.

**Spec:** G1.23 spec §7 (the lifecycle table and Claude's calls under it), §8 (G1.2 items 1–7); the G1.1 + G1.2 spec
§5.9 (event table, `served_version_id` sources), §5.10 (items, claims), §5.11.

## Global Constraints

The index's Global Constraints apply. In addition:
- **`clientActionId` is the dedupe key of `record`** (`(editor_key, client_action_id)`), so one click that writes
  several events gives each its own id: `"<clientActionId>:<opId>"` (at most 128 characters; null when the client sent
  none).
- **A reject is never refused for a stale base** (index decision 10); it is refused only for an op that is not in the
  module's kept log for that segment and occurrence.
- **`rule-suggestion` stays `noSuggestionOffered`** (always `mismatch`): no rule suggestion is offered in this version.
- **No new research vocabulary.** `suggestion-reject`, `suggestion-left-open`, `suggestion_rejection`,
  `suggestion_left_open` and `ai-suggestion` already exist in `server/lib/researchVocabulary.js`.

## Review Focus

1. **Two editors, one group** (index Review Focus 2): A rejects, B then saves with the group accepted. B's row keeps
   B's list; B's item is `mismatch`. → task 2.
2. **A dependent pair accepted in one pane** (`spatial-isomers` then `isomers`): both items `validated`, because the
   check replays the save's accepted groups in chain order, not each on its own. → task 2.
3. **Propagation and re-attach write through the same `saveSegmentEdit`** and must leave `accepted_suggestions`
   untouched on an UPDATE. → task 1.
4. **A double click on *Hafna*** inserts each op once and emits once per inserted row. → task 3.
5. **A finishing act on a row made before G1.1** (`served_version_id` NULL) closes nothing and emits nothing, and does
   not fail the act. → task 4.

### Task 1: The accepted list on save and re-save

**Files:**
- Modify: `server/services/suggestionView.js` (add `acceptedForSave`)
- Modify: `server/services/servedEdit.js` (`saveOnServedBase`: new input `acceptedSuggestions`)
- Modify: `server/services/segmentEditorService.js` (`saveSegmentEdit`: new param `acceptedSuggestionsJson`)
- Modify: `server/routes/segment-editor.js` (the save route passes `req.body.acceptedSuggestions`)
- Test: `server/__tests__/suggestionWrites.test.js`

**Interfaces:**
- Consumes: `readModuleLog`, `keptGroups` (PR1).
- Produces:
  - `acceptedForSave(log, { segmentId, occurrence, editedContent, claimed, previous }) -> string | null`: pure.
    `claimed` is the body's list (untrusted). `previous` is the union of the caller's own pending row's parsed list
    and, when the save's `displayedEditId` names **another editor's** in-flight row, that row's list (B saving on top
    of A's pending edit keeps the words A's accept put there, as long as they survive). Keeps
    each distinct `{ opId, occurrence }` from `previous ∪ claimed` whose op is in `keptGroups(log)` for that
    `segmentId#occurrence` and whose `replace` occurs in `editedContent`; returns canonical JSON sorted by `opId`, or
    `null` when nothing is kept.
  - `saveOnServedBase({ …, acceptedSuggestions })`: reads the module log once before its transaction; inside it, reads
    the caller's own pending row's `accepted_suggestions` (the same row `saveSegmentEdit`'s UPDATE path finds,
    `segmentEditorService.js:109-114`) and, if `displayedEditId` names another editor's in-flight row, that row's
    list; computes `acceptedForSave`, and passes the JSON to `saveSegmentEdit`.
  - **Two rows, on purpose:** the accepted list is merged per *editing row* (what this editor's row took), while task
    2's claim check replays on the *screen text* (whatever row was displayed). Neither is a typo of the other.
  - `saveSegmentEdit({ …, acceptedSuggestionsJson })`: writes it on INSERT and on UPDATE. **When the param is
    `undefined` (propagation, re-attach), the UPDATE leaves the column as it was** and the INSERT writes NULL.

### Task 2: The claim check (`CLAIM_VALIDATORS['ai-suggestion']`)

**Files:**
- Modify: `server/services/suggestionView.js` (add `displayedTextForSave`, `checkAcceptedGroups`)
- Modify: `server/services/researchEmission.js` (`CLAIM_VALIDATORS`, `claimAssistItems`'s `at`, `emitSave`'s call)
- Test: `server/__tests__/suggestionEmission.test.js`

**Interfaces:**
- Consumes: `moduleContext`, `staticGroupsFor` (PR1); `placeGroup` (`suggestion-placement.js`).
- Produces:
  - `displayedTextForSave(conn, saved) -> string | null`: the text that was on screen. `saved.displayed.editId` null →
    the `is_text` of `served_text_versions` row `saved.servedVersionId`; equal to `saved.editId` (a re-save of the
    caller's own row) → `saved.before.edited_content`; another id → that row's `edited_content`. `null` when it cannot
    be found.
  - `checkAcceptedGroups(conn, { book, chapter, moduleId, segmentId, occurrence, baseSha256, displayedText, savedText,
    opIds }) -> Set<string>`: the validated op ids. The groups holding the claimed ops, taken from `staticGroupsFor`,
    are applied to `displayedText` in order of their first `chainIndex`, each with `placeGroup` on the text the
    previous ones produced. A group is validated when **every one of its ops is claimed** (a group is never taken in
    part, spec §3's anti-goals), it places, and every one of its `replace` texts occurs in `savedText`; a claimed op in
    no static group, or in a group only partly claimed, is not validated.
  - In `claimAssistItems(raw, place)`, `at` gains `suggestionCheck(item) -> 'validated' | 'mismatch'`, which computes
    `checkAcceptedGroups` once per save over every `ai-suggestion` item's `opId` (memoized, as `at.offered` is).
    `emitSave` passes `{ ...placeOf(req), segmentId, occurrence: saved.occurrence, saved, editedContent }`.
  - `CLAIM_VALIDATORS['ai-suggestion'] = (item, at) => at.suggestionCheck(item)`. A throw keeps the existing
    `unverified` path.

### Task 3: The reject

**Files:**
- Modify: `server/services/suggestionView.js` (add `recordRejection`)
- Modify: `server/routes/segment-editor.js` (new route)
- Modify: `server/services/researchEmission.js` (add `emitSuggestionReject`)
- Test: `server/__tests__/suggestionWrites.test.js`, `server/__tests__/suggestionEmission.test.js`

**Interfaces:**
- Produces:
  - `POST /api/segment-editor/:book/:chapter/:moduleId/suggestions/reject`, middleware as the save route
    (`requireAuth, validateBookChapter, requireBookAccess(), validateModule`). The gate is deliberately the save
    route's: the spec says anyone who can edit the segment may reject (§7), and with enforcement off
    `hasChapterAccess` fails open for both alike. Body: `{ segmentId, occurrence,
    groupKey, baseSha256, groupActionId, clientActionId, clientActionTime }`. Answers `200 { inserted, alreadyClosed }`;
    `404 { error: 'SUGGESTION_UNKNOWN' }` when `groupKey` names no group of the module's kept log for that segment and
    occurrence; `400` on a malformed body. Organic and a book with no layer 2 answer 404 the same way.
  - `recordRejection(conn, { book, chapter, moduleId, segmentId, occurrence, group, rejectedBy, nowMs }) -> { rows,
    alreadyClosed }`: one immediate transaction; `INSERT … ON CONFLICT DO NOTHING` per change; `rows` are the inserted
    rows (with ids), `alreadyClosed` the count of ops already in either table.
  - `emitSuggestionReject(req, { rows, servedVersionId, offeredOpIds, groupActionId, echoedBaseSha256, baseMismatch })`:
    one `suggestion-reject` event per row: `editingKind 'suggestion_rejection'`, `editingId row.id`, `segmentId`,
    `occurrence`, `servedVersionId`, `clientActionId "<id>:<opId>"`, one item `{ itemType: 'ai-suggestion', source:
    'ai', opId, occurrence, category, runId, rulingId, groupActionId, claim }` with `claim` `validated` when the op was
    in `offeredOpIds`, else `mismatch`; `detail { echoedBaseSha256, baseMismatch }`.

The route mints the current base for the segment the way `saveOnServedBase` does (read `servedEdit.js:118-260` and
reuse its mint call, not a copy of it); `baseMismatch` is `echoed !== current`. It looks the group up in
`keptGroups(log)` (not in the offered set, so a stale screen can still reject), computes `offeredOpIds` from
`staticGroupsFor` on the current base, writes, then emits.

### Task 4: Left open at the two finishing acts

**Files:**

**Interfaces:**
- Consumes: `moduleContext`, `staticGroupsFor`, `visibleGroups`.
- Produces:
  - `closeLeftOpen(conn, { book, chapter, moduleId, segmentId, occurrence, servedVersionId, act, finishingKind,
    finishingId, finishedText, acceptedOps, closedBy, nowMs }) -> rows`. Never throws (a failure warns and returns
    `[]`). Reads the base hash from `served_text_versions` row `servedVersionId` (NULL id → `[]`); open groups are
    `staticGroupsFor` minus any group with an op in `acceptedOps`; `shown_at_finish` is 1 when `visibleGroups(
    finishedText, open)` includes the group; one row per change, `ON CONFLICT DO NOTHING`, in one immediate transaction.
  - At *Staðfesta MT*: called only when `result.alreadyAccepted` is false, with `act 'stadfesta-mt'`,
    `finishingKind 'segment_acceptance'`, the acceptance's id, `served_version_id` and `accepted_content`, and
    `acceptedOps []`.
  - At approval: `act 'approval'`, `finishingKind 'segment_edit'`, the edit's id, `served_version_id`,
    `edited_content` and parsed `accepted_suggestions`, with the place taken from the edit row.
  - `emitSuggestionLeftOpen(req, { rows, act, servedVersionId })`: one `suggestion-left-open` event per row,
    `editingKind 'suggestion_left_open'`, one item (claim `validated`), `detail { act, shownAtFinish }`,
    `clientActionId null`. For approval the place comes from the edit row as `emitReview` does (`rowPlace`, `editRef`
    at `researchEmission.js:518-537`); for *Staðfesta MT* from the route, as `emitAccept` does.
