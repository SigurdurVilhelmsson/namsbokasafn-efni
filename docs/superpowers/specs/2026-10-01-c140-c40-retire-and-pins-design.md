## Scope

**This PR:** two config tables (both empty), their handling in `sources.py`, a new tool
`tools/retire-translated-figure.js`, the mapping generator honouring the retired record, the wording of
`figure-run.js`'s refusal messages, a config validator, tests, docs, and the PR-time text fixes in D12.

**Not this PR:** any retired entry or pin; deleting any figure; re-inject or re-render; any buy; anything in vefur.
Those are the steps after merge (§ Run order).

## Terms

- **Translated copy:** `books/<book>/media/<name><DEFAULT_SUFFIX>.<ext>`, top level only. `DEFAULT_SUFFIX` is owned
  by `tools/generate-image-mapping.js`; this document never restates its value.
- **Published copy:** `books/<book>/05-publication/<track>/chapters/<dir>/images/media/<name><DEFAULT_SUFFIX>.<ext>`.
- **The corpus (D13):** the working-tree content of every file git does not ignore under the book's `03-translated/`
  and `05-publication/`, raster and font files skipped. ✏️ *Amended 2026-10-01 during planning: the translated copies themselves are skipped too, see D13.*
- **A reference to `<name>`:** the string `<name><DEFAULT_SUFFIX>.` in a corpus file that is not itself a copy of
  that file.

The rules above read only the declared path, which a symlink defeats. The normal lookup is unchanged; the real trees hold 0 symlinks.* ✏️ *Amended 2026-10-02 at the final review: a malformed pin stays a per-figure refusal, but a malformed TABLE does not: see D6's amendment of the same date.* | Fail closed per figure. ## Interfaces

```text
node tools/retire-translated-figure.js --book <slug> --retire <name>[,<name>…] [--apply]
node tools/retire-translated-figure.js --book <slug> --prune [--apply]
```

Exit codes: `0` done, or the dry-run plan printed with nothing refused; `1` refused, or failed after a write and
restored; `2` usage.

```json
"retiredFigures": { "<basename>": "<what was ruled, and why>" },
"artworkPins": {
  "<basename>": { "kind": "alias", "edition": "updates-2e", "file": "<path inside that tree>", "reason": "<what was ruled, and why>" }
}
```

A pinned hit from `sources.py --json`: `{"path", "edition", "via": "alias"|"override"[, "pageUnknown": true]}`.
A refusal: `{"path": null, "refused": "retired"|"pin-conflict"|"pin-missing"|"pin-invalid", "edition", "candidates",
"reason"}`, each candidate `{path}` plus `page` and `paper` when known. ✏️ *Amended 2026-10-02 at the final review: a `production-page` refusal of a PINNED file also carries `via`, as a pinned hit does (D7).*

## Known limits

- **A sidecar records no artwork provenance** (459 of 459 checked; `isStale` compares hashes only), so a pin
  changed after a buy is invisible to `--stale`. Accepted for four hand-bought figures.
- **Once bought, a pinned figure is filed `skipped-current` before it is resolved**, so `pin-conflict` surfaces only
  on a by-hand `sources.py` check, `--force`, or a `--stale` run after a composer bump. A `sources.py` check of the
  pinned names belongs in each chemistry lineup.
- **The census and read-layer scripts do not see the new tables**, just as they do not see `supersededArtwork`.
- **The tables are global, not book-scoped;** the validator requires each key to name an image in exactly one
  book's `01-source`.
- **The retire tool's mapping helpers** (parse-or-refuse, atomic write, restore) follow `figure-run.js`'s
  module-local ones rather than sharing them; extracting a shared module would touch the paid driver (logged).
- **vefur:** a deleted published copy leaves the mt-preview mirror at the next sync; faithful files are laid on top
  without deletion. A same-name recompose reaches readers who installed the site as an app late, because vefur's
  service worker caches `/content/*.svg` for 30 days (inferred from vefur's config; vefur's to confirm).
