## The question

§C140 ⑥ proposes drawing symbol-font glyphs (`+ = ×`) in their real STIX face instead of Liberation Sans, where they
sit about 2 px high. The 2026-09-13 prototype **extracted** each source PDF's embedded STIX subset and rebuilt it into a
font named `FigSTIX` (`../2026-09-13-compose-fidelity/instruments/2a/stixface.py`); the register logged it as a
*"[LEAD] provenance call: extracting OFL STIX subsets from OpenStax PDFs"*. [USER] asked on 2026-09-16 whether STIX has
licensing complications.

## What the OFL and SIL's documents say

`OFL.txt` is the licence. The **OFL-FAQ** and the **Webfonts and Reserved Font Names** paper are SIL's explanatory
documents, not the licence text.

- **Licence, condition 3:** *"No Modified Version of the Font Software may use the Reserved Font Name(s) unless explicit
  written permission is granted by the corresponding Copyright Holder. This restriction only applies to the primary font
  name as presented to the users."* (#12)
- **Licence, condition 2:** copies *"bundled, redistributed and/or sold with any software"* must each contain *"the above
  copyright notice and this license"*, which may sit *"in the appropriate machine-readable metadata fields within text or
  binary files as long as those fields can be easily viewed by the user"* (#21).
- **FAQ 1.12:** *"Yes, either in full or a subset. The restrictions regarding font modification and redistribution do not
  apply, as the font is not intended for use outside the document."* (#1)
- **FAQ 1.13:** *"Referencing or embedding an OFL font in any document does not change the license of the document
  itself."* (#2)
- **FAQ 1.10:** a font may travel without the OFL text only when it *"is embedded in a document or bundled within a
  program"*; for font metadata a link to the OFL text is *"legally sufficient"*, *"but we strongly recommend against
  this"* (#20).
- **FAQ 1.14, extraction:** OFL fonts *"marked as such by the author(s)"* are *"intended to remain under this license
  regardless of the distribution method"*, and *"We strongly discourage any font extraction - we recommend directly using
  the font sources instead"* (#27).
- **Paper:** *"When the modification of the font is clearly only part of the embedding process - such as in a PDF - RFNs
  are allowed."* (#16)
- **FAQ 1.16:** *"The requirements differ depending on whether the fonts are linked, embedded or distributed (bundled or
  aggregated). Some ebook formats use web technologies to do font linking via @font-face, others are designed for font
  embedding …"* (B)

## The grey area — what is an SVG with an inlined font?

Our figures are SVG files with the font inlined as a base64 `@font-face` data URI. **No fetched text addresses that**
(U2, U3). The texts offer three categories, and FAQ 1.16 names `@font-face` in its *linking* example — but for ebooks,
not for a font inlined inside the file:

- **Embedding** — FAQ 1.11: inclusion *"in a way that makes extraction (and redistribution) difficult or clearly
  discouraged"* (#7). If this applies, a subset is permitted (1.12) and reserved names are allowed (paper, #16).
- **Distribution** — FAQ 1.11: *"Any other means of delivering a font to another person is considered 'distribution',
  and needs to be accompanied by any copyright notices and licensing information available in OFL.txt."* (#7)
- **Webfont** — FAQ 2.6: subsetting *"is considered modification. This is permitted by the OFL but would not normally
  allow the use of RFNs"* (#8), with 2.7's Functional-Equivalence exception (#17); the paper treats pre-subset fonts as
  *"a Modified Version for which RFN restrictions apply"* (#11). The restricted name covers *"the font menu name and other
  mechanisms that specify a font in a document"* (5.3, #14); *"You may not use individual words from the Reserved Font
  Names, but you would be allowed to use parts of words"* (5.4, #35).

**What the texts name, if the stricter readings apply** — whether meeting them is sufficient is not settled (U1, U16):

1. **Reserved names:** a Modified Version may not use a reserved name as its primary font name, including *"other
   mechanisms that specify a font in a document"* (condition 3, 5.3), nor individual words of one (5.4). *Our mapping,
   not the texts':* in OpenType that concerns the name records IDs 1, 3, 4, 6, 16, 17, 21, 22 and, in our SVGs, the CSS
   `font-family`. How "STIX Fonts" applies to a `STIXGeneral` derivative — including whether `FigSTIX` uses a word of it —
   was deliberately not interpreted (U16).
2. **Notices:** copyright statements may not be removed (3.1, #13); *"Any trademark notices must remain in any derivative
   fonts"* (3.7, #19). For STIX 1.1.0 those are IDs 0 and 7; ID 7 contains "STIX Fonts" as a notice, not as a font name.
3. **Licensing information:** distribution needs the licensing information from `OFL.txt` (#7), and condition 2 accepts
   metadata only *"as long as those fields can be easily viewed by the user"* (#21). STIX 1.1.0's own ID 13 carries no OFL
   text and no version, only an old SIL link; FAQ 1.10 calls a link alone *"legally sufficient"* but *"strongly
   recommend[s] against"* it (#20).

The 2026-09-13 prototype sets family `FigSTIX`, passes only a family and a style name to `setupNameTable` and only a
`FullName` to `setupCFF` (`stixface.py`, `build_otf`) — so neither its name table nor its CFF data is given a copyright
or trademark notice.

  Reserved Font Name Liberation."* (§5). The OFL grey area above applies to this population.

## Limits

- STIX: Regular was compared across all 162 subsets; the other faces, the TrueType objects and the EPS files were not.
  109 glyph widths could not be mapped. The release is identified by its Notice string; 1.1.1 and pre-1.0 betas (U10) were
  not compared.
- How the reserved names apply to a subset of a `STIXGeneral` font was deliberately not interpreted (U16).
- Liberation: the 1.07.4 licence is the release's `License.txt`; the Fedora page its name record links was not fetched,
  and no document says whether an inlined subset is "embedding" under exception (a). What the website serves was not
  compared.

## Reproducing

```bash
cd experiments/figure-text-translation
S=/tmp/stix-evidence && mkdir -p $S
curl -fLo $S/STIXGeneral-Regular-1.1.0.otf \
  https://raw.githubusercontent.com/stipub/stixfonts/master/archive/STIXv1.1.0/Fonts/STIX-General/STIXGeneral-Regular.otf
curl -fLo $S/STIXGeneral-1.0.0.otf \
  https://raw.githubusercontent.com/stipub/stixfonts/master/archive/STIXv1.0.0/Fonts/STIXGeneral.otf
curl -fLo $S/lib.tar.gz https://releases.pagure.org/liberation-fonts/liberation-fonts-ttf-1.07.4.tar.gz && tar xzf $S/lib.tar.gz -C $S
sha256sum $S/*.otf $S/lib.tar.gz          # compare with reports/network-captures.txt § A
PYTHONPATH=./pylibs python3 evidence/2026-09-16-stix-licence/instruments/local_fonts.py \
  --stix110 $S/STIXGeneral-Regular-1.1.0.otf --stix100 $S/STIXGeneral-1.0.0.otf \
  --liberation1074 $S/liberation-fonts-ttf-1.07.4
```
Needs poppler's `pdffonts`; `fontTools` and `brotli` in `pylibs/`; `pikepdf` importable (a system package on the box that
ran this); the gitignored `sources.local.json`. The STIX downloads come from a `master` branch, which can change — the
sha256s in A are the reference.
