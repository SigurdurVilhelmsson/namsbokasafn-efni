## Two design consequences that are NOT obvious from the plan

1. 🔴 **The verdict keys on `segmentsWithDelta`, never on `total`.** The instrument
   deletes types whose per-segment deltas sum to zero (`api-translate.js:612`, comment:
   *"noise in `total` but their segments are already counted in segmentsWithDelta"*), so
   a module losing a `MATH` in one segment and gaining one in another has **`total == {}`**
   and two `bySegment` entries. Per-segment computation exists precisely to defeat that
   cancellation; keying on `total` throws away the reason §C69 widened the check.
   ⚠️ **The plan's acceptance trio is written in `total`-shaped notation** (`m68791 → {}`),
   so a literal transcription ships the cancelling design.
   ⚠️ **AND THE CORPUS CANNOT CATCH THAT MISTAKE: measured `P1 − P2 = 0` — the two
   predicates are INDISTINGUISHABLE on all 197 pairs.** Only a planted cross-segment
   +1/−1 fixture separates them. This is the L44③ shape: a natural corpus of 0 is exactly
   what a wholly broken detector returns.
2. ⚠️ **`unpairedSegIds` is a SEPARATE finding, folded in deliberately.** The instrument's
   own docstring: *"a missing occurrence is a worse defect than a marker delta and a
   comparison that quietly drops it reads as clean."* Reading only `bySegment` passes a
   module whose segments went missing. Measured cost of folding it in: **4 modules,
   2.03%** — it does not change the blocking verdict either way.

## A7 — the port is bigger than "~20 lines", and it carries INVISIBLE CHARACTERS

🔴 **`checkNumbers` cannot be ported alone.** It calls `extractNumbers`, which calls
`stripMath(stripMarkers(text))` — both private to `qaCheckService.js`.
🔴 **AND `tools/lib/residue-check.js`'s `stripMarkers` IS NOT A SUBSTITUTE.** The two are
materially different: qaCheckService's **drops `xref`/`docref` entirely** and unwraps
`{{type}}…{{/type}}` pairs and `++…++`; residue-check's **keeps the text before `|` for
every type** and drops `[#id]`. Swapping them changes which numbers are extracted.
▶ Port `stripMath` + `stripMarkers` + `extractNumbers` + `numberKey` + `checkNumbers`
as a set, and pin the set against the AGPL original in a test.

🔴 **BOTH `extractNumbers` REGEXES CONTAIN NON-ASCII WHITESPACE, AND A HAND
TRANSCRIPTION SILENTLY LOSES IT.** Measured by code point, not by eye:

| line | literal | invisible members |
|---|---|---|
| `:67` | `/\d[\d.,␣]*\d|\d/g` | **U+00A0** (NBSP), **U+2009** (THIN SPACE), U+0020 |
| `:69` | `/[.,␣]+$/` | **U+00A0**, **U+2009**, U+0020 |

This is load-bearing, not decorative: **NBSP and thin space are exactly the thousands
separators European/Icelandic number formatting uses**, so dropping them changes what
`1 000` parses as. It is also precisely the class CLAUDE.md § *invisible control bytes*
warns about — the characters do not render, so the port looks correct in a diff.
▶ **Write them in the port as explicit `  ` escapes** — behaviourally identical,
visible to a reader and to a grep, and impossible to lose to an editor that normalises
whitespace. **The equivalence test is what proves "behaviourally identical" rather than
assuming it.**

⚠️ `numberKey` strips every non-digit, so **`3.5` and `35` collide** — its own comment
calls it a heuristic and accepts collisions for a warning. That is one more reason A7 is
ADVISORY. **Do not port `checkEnResidue`** (the §C67 over-reporter).
