  Chemistry's wrapper is unprefixed <metadata ...> (resolves into the collxml default namespace,

  <md:license ...> or <col:subcollection ...> — both of those retain their literal prefix in BOTH
  files — but it means Task 3's parser must not assume the wrapper tag's prefix, only the leaf
  tags actually consumed.

Interpretation — THIS IS THE LOUD FINDING, EXACTLY AS THE BRIEF SET UP:
  Today, upstream chemistry's collection XML says CC BY-NC-SA 4.0 — NOT CC BY 4.0.
  Chemistry's LOCAL copy (books/efnafraedi-2e/) was obtained 2026-01-19 under CC BY 4.0
  (docs/provenance/openstax-cnxml-licence-provenance.md §1, "CONFIRMED"), well before the
  2026-04-23 per-collection relicense flip documented there. So the live upstream value observed
  here (CC BY-NC-SA) diverges from the locally-recorded licence (CC BY) — this is *precisely* the
  substitution scenario the C93 guard exists to prevent: a naive re-download today would silently
  replace the irrevocable CC BY copy's provenance basis with CC BY-NC-SA bytes. This was expected
  going in (CLAUDE.md already names Chemistry as a book needing this protection) — it is not a new
  discovery, but it IS a live, freshly-measured confirmation, not a citation of the 2026-06-24
  investigation.

STEP 3 — Interpretation / verdict for G3's premise
----------------------------------------------------------------------------------------------------

VERDICT: NOT BLOCKED. <md:license url=…> IS present in upstream collection XML today, in both
books checked, in the exact shape G3 needs: a self-closing-attribute-bearing element,
`<md:license url="…">…</md:license>`, holding a Creative Commons URL. The premise holds — G3 can
be built as specified, parsing this element out of a freshly fetched collection XML and comparing
its `url` against the locally recorded licence.

Distinct licence URLs OBSERVED in this task's live fetches (for Task 3's closed enum):
  - http://creativecommons.org/licenses/by-nc-sa/4.0/   (organic today; chemistry today)

That is the ONLY value this task's live HTTP fetches actually produced — both books currently
resolve to CC BY-NC-SA upstream, so only one URL was observed live. Task 3 will need a second
enum member for CC BY 4.0 (http://creativecommons.org/licenses/by/4.0/) to cover the three books
still legitimately CC BY locally (Chemistry, Biology, Microbiology) — that exact URL string is
NOT re-verified by this task's live fetch (upstream no longer serves it for chemistry), but it is
corroborated by two independent sources: (a) docs/provenance/openstax-cnxml-licence-provenance.md
§2's `git log -S 'licenses/by/4.0'` census on the same four repos, and (b) this task's own
observation that BOTH files use the identical element/attribute shape
`<md:license url="...">...</md:license>` — only the url value and human-readable text between the
tags differ between the CC BY and CC BY-NC-SA cases, per the diff already captured in the
provenance doc §2. Task 3 should treat the CC BY url as "known shape, not live-reconfirmed today"
and cite the provenance doc, not this file, for that half of the enum.

Format note for Task 3's parser: match `<md:license\s+url="([^"]+)"` — works against both files'
literal text regardless of the `<col:metadata>` vs unprefixed `<metadata>` wrapper difference noted
above, since only the wrapper tag differs, not the `<md:license>` leaf.
